### Компоненты и ответственность

`Kitchen API` является основной точкой входа в систему. Он предоставляет REST API для получения ресторанов и меню, создания заказов, получения информации о заказе и изменения его статуса.

`Restaurant Sync` отвечает за интеграцию с внешней системой ресторана. В рамках MVP он получает данные ресторана и меню через API демонстрационного ресторана и синхронизирует их с основной базой данных.

`PostgreSQL` является основной базой данных системы. В ней хранятся данные ресторанов, меню, пользователей, адресов, заказов и связанных справочников.

`Restaurant Mock API` имитирует внешнюю систему заведения и запускается вместе с основным приложением через Docker Compose.

`Alembic` используется для управления миграциями схемы PostgreSQL.


## Схема базы данных

Для хранения данных используется PostgreSQL. Доступ к базе данных реализован через SQLAlchemy ORM, изменения схемы управляются с помощью Alembic.

Основные сущности системы:

* `customers` — пользователи сервиса;
* `addresses` — адреса пользователей;
* `restaurants` — заведения;
* `menu_categories` — категории меню;
* `menu_items` — блюда и товары меню;
* `delivery_types` — типы получения заказа;
* `order_statuses` — статусы заказов;
* `orders` — заказы пользователей;
* `order_items` — позиции заказа.

Связи между основными сущностями:

```text
Customer 1 ───── N Address

Restaurant 1 ───── N MenuCategory
Restaurant 1 ───── N MenuItem

Order N ───── 1 Customer
Order N ───── 1 Address
Order N ───── 1 Restaurant
Order N ───── 1 DeliveryType
Order N ───── 1 OrderStatus

Order 1 ───── N OrderItem
MenuItem 1 ───── N OrderItem
```

`order_items` содержит снимок основных данных позиции заказа (`name`, `price_per_item`, `quantity`). Это позволяет сохранить состояние заказа независимо от последующих изменений меню ресторана.

`orders` также содержит снимок адреса доставки на момент оформления заказа. Поэтому изменение пользовательского адреса после оформления не изменяет исторические данные уже созданного заказа.

Для интеграции с внешними системами используются внешние идентификаторы (`external_id`). Они позволяют связывать сущности основного сервиса с соответствующими сущностями внешнего сервиса ресторана.

Миграции базы данных находятся в:

```text

```

## Web Client

Проект содержит web-клиент для демонстрации пользовательского сценария
заказа еды.

Web-клиент реализован на React + TypeScript + Vite.

### Пользовательский сценарий

1. Пользователь открывает список ресторанов.
2. Выбирает ресторан.
3. Просматривает меню.
4. Добавляет блюда в корзину.
5. Использует сохранённый адрес и тип доставки.
6. Создаёт заказ.
7. Получает информацию о созданном заказе.
8. Просматривает текущий статус заказа.

### Допущения
- Web-клиент работает от имени клиента №2.
- Для оформления заказа используется адрес клиента №2.
- Используется тип доставки №3.
- Авторизация пользователя в рамках MVP отсутствует.

### Запуск

Web-клиент запускается вместе с остальными сервисами
